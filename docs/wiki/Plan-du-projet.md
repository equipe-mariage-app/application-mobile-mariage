# Plan du projet

| Étape | Démonstration attendue |
| --- | --- |
| Socle | Une PR relue passe la CI. L’environnement Flutter démarre sur deux postes. |
| Exploration | Un visiteur cherche et ouvre une fiche sans compte. |
| Publication | Un propriétaire publie une salle sur Android. Le visiteur la retrouve. |
| Disponibilités et réservation | Le propriétaire ajoute des dates. Le visiteur les consulte et reprend la réservation de la même salle après connexion. |
| Rendu | L’équipe montre l’application, les tests, les preuves d’évaluation et le travail GitHub. |

Le [plan détaillé](https://github.com/Kemadjou-Cabrel/application-mobile-mariage/blob/main/docs/plan-travail-sallio.md) définit les responsabilités et les preuves. Le [backlog](https://github.com/Kemadjou-Cabrel/application-mobile-mariage/blob/main/docs/backlog-sallio.md) documente les 36 stories. Le tableau Projects porte les affectations, priorités, statuts et dates d’itération.
